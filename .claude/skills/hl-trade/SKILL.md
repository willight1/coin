# 하이퍼리퀴드 주문·잔고 계산

기능 상세는 `docs/HL_AGENT.md`. 여기는 매번 하는 절차와 함정만.

## 1. 지금 상태부터 읽는다 (항상)

```bash
./venv/bin/python -c "
import json;s=json.load(open('state/hl_live.json'))
print('평가',s['equity_usd'],'넣은돈',s.get('net_in_usd'),'시세',s['marks'])
print('포지션',json.dumps(s['pos'])); print('예약',json.dumps(s['resv'],ensure_ascii=False))
print('대기',s['pending'],'수동',s.get('manual'),'멈춤',s.get('hold'))"
```

- `pos.size` 양수 = 롱, 음수 = 숏. **기억 속 수량을 쓰지 말 것** — 봇이 4시간봉마다 양을 바꾼다.
- `load_hl_config()` 결과·`.env` 는 출력하지 않는다.
- 환율: 업비트 KRW-USDT 시세(`https://api.upbit.com/v1/ticker?markets=KRW-USDT`). 못 받으면 약 1,365원이라고 밝히고 쓴다.

## 2. 계산 공식

- 가격 P 에서 계좌 = `equity + size × (P − mark) − |size|×P×0.00015`(지정가 수수료)
- 수익 기준은 **넣은 돈 합계 `net_in_usd`** (킬 기준 `start_usd` 와 다르다. 대시보드 '순이익'도 net_in_usd).
- 목표 수익률 r 가격: `P = mark + (net_in×(1+r) − equity) / size` (롱 기준, 수수료 약 1달러 더함)
- 청산가(교차, 코인 하나): `L = (size·mark − equity) / (size·(1 − 1/(2·최대배수)))`, BTC 최대 40배 → m=1/80.
- 출금 가능액은 명목가의 10% 를 남겨야 한다.
- 결과는 표로: 달러·원화·넣은 돈 대비 %. 보유량이 바뀌면 결과도 바뀐다고 한 줄 적는다.

## 3. 명령 문법

| 하려는 것 | 명령 |
|---|---|
| 지금 전부 정리 | `/hl_close btc` |
| 지금 일부 팔기(롱 보유 시) | `/hl_short btc <달러명목>` — 롱이 줄어든다 |
| 늘리기 | `/hl_long btc <달러>` · `10x` · `100 20x` |
| 가격 예약 | `/hl_at btc <가격> close\|long 금액\|short 금액 up\|down` |
| 목록·취소 | `/hl_list` · `/hl_cancel 번호\|all` |
| 봇에 되돌리기 | `/hl_auto btc` |

- 비율 매도 금액 = `|size| × 비율 × 그 가격`. **"25%"는 지금 남은 양 기준인지 처음 양 기준인지 모호하면 지금 양으로 하고 그렇게 말한다.** "25% 남기고 팔아" = 지금 양의 75%.
- 예약에는 항상 `up`(지금보다 위) / `down`(아래)을 붙인다.

## 4. 걸기 전 충돌 검사 (필수)

하이퍼리퀴드는 코인당 포지션 하나다. 반대 방향 주문이 보유량보다 크면 **반대 포지션이 새로 생긴다.**

1. 기존 예약 전부 + 새 주문이 같은 방향으로 실행된다고 가정하고 남는 양을 더한다. 0 아래로(롱→숏) 넘어가면 걸지 말고 알린다.
2. 부분 매도 예약이 여러 개면 앞의 것이 실행된 뒤 뒤의 금액이 남은 양보다 클 수 있다 → 마지막 것은 `close` 로.
3. `close` 예약은 그때 남은 양을 다 판다. 이미 `close` 예약이 있으면 새 매도 예약과 겹치는지 말한다.
4. 박스·단타 코인에는 직접 주문·예약을 걸지 않는다(가격이 닿아도 거절된다).
5. `pending` 이 비어 있지 않으면 앞 주문이 아직 체결 중이다 — 알리고 기다린다.
6. 4시간봉 마감(KST 1·5·9·13·17·21시) 앞뒤 몇 분은 봇이 양을 바꾸는 중일 수 있다 — 비율 주문이면 알리고, 마감 뒤 `pos` 를 다시 읽고 계산한다.
7. 직접 주문·예약 실행 뒤 그 코인은 `state.manual` 이 되어 4시간 재조정이 멈추고 이익 보호만 걸린다. 주문할 때 "봇 자동매매로 되돌리려면 `/hl_auto btc`"를 한 줄 알린다.

## 5. 보내기

사용자가 직접 시킨 주문은 확인까지 한 번에:

```bash
echo '/hl_do /hl_at btc 67300 close up' >> state/hl_commands.txt
```

- `/hl_do` 는 명령 하나만 확정한다. 줄마다 하나씩.
- 약 30초 뒤 `state/hl_live.json` 의 `resv`·`pos` 나 `logs/hl_chat.jsonl` 끝줄로 들어갔는지 확인하고 결과를 알린다.
- 지금 주문은 지정가라 몇 초~몇 분 걸린다. "취소"가 와도 이미 체결됐을 수 있다 — `logs/hl_trades.csv` 로 확인해 사실대로 말한다. 실현 수익도 이 파일의 체결 행(수수료 포함)으로 계산한다. 추정하지 말 것.
- 예약은 거래소에 걸리는 주문이 아니다. 봇이 30초마다 보고 닿으면 지정가로 낸다(찍고 돌아온 가격은 놓칠 수 있다).
