## 3. 에이전트 입력 (모든 지표)

### 3-1. 봉
- 1분, 3분, 5분, 10분, 15분, 30분, 60분, 240분, 일봉, 주봉. 각 200봉을 받아 **마감 봉으로** 지표를 계산하고, 진행 중 봉은 따로 표시한다.
- 최근 마감 캔들 원본 `[시각, 시가, 고가, 저가, 종가, 거래대금(백만원)]`: 5분·15분·60분·240분·일봉은 8개씩, 나머지 봉은 지표 요약만.

### 3-2. 봉별 지표
- 가격: 종가, 1봉·12봉 변화율, 돈치안20 위치, 직전 20봉 고가·저가까지 거리
- 추세: EMA9/21/50/100 정배열 여부, 종가 대비 EMA50·EMA100 괴리, ADX14, +DI/−DI
- 모멘텀: RSI14와 직전 값, RSI70 상향 돌파 후 경과 봉 수, MACD(12,26,9) 히스토그램과 직전 값, 스토캐스틱(14,3)
- 변동성: ATR14(%), 볼린저(20,2) %B와 밴드폭, 밴드폭의 최근 100봉 백분위
- 거래량: 거래대금/20봉 평균, 거래대금 z점수, OBV 20봉 기울기, 양봉 거래대금 비중

### 3-3. 시장
- 현재가, 전일 대비, 24시간 거래대금, 세션(09:00) VWAP과 괴리
- 호가: 최우선 매수·매도, 스프레드 bp, 상위 5·15호가 잔량과 불균형
- 체결: 최근 200건 매수 체결 비율, 걸린 시간, 1분 내 대량 체결 여부
- 유의종목 여부, 다음 FOMC·CPI 발표까지 남은 시간(설정 파일 `state/dt_events.json`)

### 3-4. 전략 상태
- 라이브러리 전략별 현재 신호 상태(기본 파라미터 기준 진입 신호 여부, 보유 구간 여부)
- 점수판: 전략별 최근 7·30·90일 주문 없는 계산 성과(수익, 거래, 승률, MDD)와 2-1 장기 근거
- 현재 플랜(전략, 파라미터, 설정 시각, 이유)과 플랜 변경 가능 시각

### 3-5. 내 상태
- 포지션(수량, 진입가, 진입 전략, 미실현 %, 보유 시간, 손절가)
- 오늘 매수 횟수, 오늘·7일 손익, 남은 예산, 재량 매매 사용 비중
- 최근 판단 5개(행동, 이유, 그 뒤 가격 변화)와 최근 거래 5건(전략, 이유, 결과)
- 교훈 메모(`state/dt_lessons.md`, 최대 30줄)

## 4. 에이전트 출력 (JSON만)

```json
{
  "regime": "상승추세|하락추세|횡보|고변동|이벤트대기",
  "plan": {
    "strategy": "rsi_momo_1h|rsi_momo_4h|breakout_vol_1h|sma_trend_daily|vb_daily|vwap_revert|discretionary|none|keep",
    "params": {},
    "size_pct": 50,
    "stop_loss_pct": 3.0,
    "reason": "이 전략을 고른 근거"
  },
  "action": "follow_plan|buy_now|sell_now|hold",
  "action_size_pct": 0,
  "confidence": 0.0,
  "next_check_min": 15,
  "reason": "판단 근거 두세 문장"
}
```

- `plan.strategy = keep`이면 현재 플랜 유지
- `size_pct`: 플랜이 매수할 때 예산 대비 비중(25~100)
- `action`: `follow_plan`은 실행기에 맡김, `buy_now`는 즉시 매수(재량 한도 적용), `sell_now`는 즉시 매도(`action_size_pct` = 보유 대비 비중), `hold`는 아무것도 안 함
- `next_check_min`: 다음 LLM 호출까지 분(5~60). 이벤트가 생기면 더 일찍 깨운다(6장)
- 범위 밖 값은 잘라내고, 형식이 깨지거나 호출이 실패하면 현재 플랜 유지 + `hold`

## 5. 실행기 동작
- 플랜의 전략을 캔들 마감마다 집행한다. 진입 신호가 나고 리스크 가드를 통과하면 매수, 청산 조건이 되면 매도한다.
- 플랜 변경 규칙
  - 플랜은 설정 후 `DT_MIN_PLAN_HOLD_MIN`(60분) 동안 바꿀 수 없다. 단 `none`으로 바꾸기와 `sell_now`는 언제나 가능
  - 보유 중에 전략을 바꾸면, 새 전략이 보유를 인정하는 상태(예: 새 전략도 보유 구간)면 포지션을 넘겨받고, 아니면 다음 판단까지 기존 전략의 청산 규칙을 유지한다
- 포지션은 1개, 추가 매수 없음
- 손절가는 체결가 × (1 − stop_loss_pct), 10초마다 확인
- `sma_trend_daily`를 제외한 전략은 `DT_MAX_HOLD_HOURS`를 넘으면 매도
- `vwap_revert`는 지정가(post_only)로 주문하고, 진입 조건이 풀리거나 30분 안에 체결되지 않으면 취소. 09:00에 보유분 강제 청산
- `buy_now`는 재량 매매로 기록하고 예산의 `DT_DISCRETIONARY_MAX_PCT`를 넘지 못한다

## 6. 호출 일정
- 기본: 에이전트가 정한 `next_check_min`(5~60분) 뒤
- 바로 깨우는 이벤트(LLM 호출)
  - 1시간봉·4시간봉·일봉 마감
  - 라이브러리 전략 중 하나에서 새 진입 신호
  - 마지막 판단 이후 가격이 `DT_WAKE_MOVE_PCT`(1.0%) 이상 움직임
  - 1분 거래대금이 직전 60분 평균의 3배 이상
  - 체결 발생(매수·매도·손절)
  - FOMC·CPI 발표 30분 전과 60분 뒤
- 하루 LLM 호출 상한 `DT_MAX_LLM_CALLS_PER_DAY`(200). 넘으면 다음 날까지 현재 플랜만 실행

7. 확신도 ≥ 기준
8. 스프레드 ≤ 기준, 유의종목 아님
9. 재량 매매면 재량 한도 이내
10. 주문 금액 = `min(DT_BUDGET_KRW × size_pct, 원화 가용 잔고 × 0.995)` ≥ 6,000원

## 8. 주문
- 시장성 주문: 최유리 지정가 IOC
  - 매수 `{"market":"KRW-BTC","side":"bid","ord_type":"best","time_in_force":"ioc","price":"<원화 금액>","identifier":"dt-<uuid>"}`
  - 매도 `{"market":"KRW-BTC","side":"ask","ord_type":"best","time_in_force":"ioc","volume":"<수량, 소수 8자리 내림>","identifier":"dt-<uuid>"}`
- `vwap_revert` 지정가: `ord_type=limit`, `time_in_force=post_only`, 가격은 BTC 호가 단위(1,000원)에 맞춤. 미체결 주문 관리(조회·취소) 포함
- 순서: `POST /v1/orders/test`(별도 identifier) → `POST /v1/orders` → `GET /v1/order?uuid=`로 상태 확인 → 체결 목록에서 수량·평균가·수수료 계산
- 매수 95% 미만 체결이면 남은 금액으로 1회 재시도. 매도 잔량은 1회 재시도 후 시장가(`ord_type=market`)로 마무리
- 응답이 끊기면 재주문하지 말고 `identifier`로 조회
- 매도 수량 = 봇 기록과 BTC 가용 잔고 중 작은 값
- 예약주문(스톱지정가, 수수료 0.139%)은 쓰지 않는다
- 체결마다 판단 시점 중간가 대비 슬리피지(bp) 기록, 10bp 넘으면 경고. 주문 오류 연속 3회면 신규 매수 중지

시작·복구
- `DT_LIVE_CONFIRM=yes`가 있어야 실제 주문
- 시작 시 `GET /v1/accounts`와 주문 테스트로 키·권한·IP 확인, 실패하면 시작 안 함
- 계좌에 BTC가 있는데 봇 기록이 없으면 `avg_buy_price`로 넘겨받고, 첫 판단에서 에이전트가 처리 전략을 정한다
- 1시간마다 봇 기록과 BTC 잔고 대조, 어긋나면 신규 매수 중지 후 알림
- 종료 시 포지션은 두고 상태 저장, 재시작하면 이어서 관리

## 11. 시스템 프롬프트 (`bot/prompts/dt_system.md`)

```text
너는 업비트 KRW-BTC 현물 자율 트레이딩 에이전트이자 전략 매니저다. 실제 돈으로 주문된다.
판단 시점마다 BTC 시장 스냅샷(JSON)을 받고, 시장 국면을 판단해 전략 라이브러리에서 전략을 고르고 파라미터를 정한다. 필요하면 즉시 매수·매도한다.

[거래 환경]
- 현물 롱 전용이다. 하락장에서 돈을 버는 방법은 없고, 현금(none)으로 있는 것이 하락장 대응이다.
- 수수료는 편도 0.05%, 왕복 0.1%다. 1~5분봉 한 봉의 평균 변동폭은 왕복 비용보다 작다. 자주 사고팔수록 비용으로 진다.
- 예산, 손실 한도, 손절 범위, 거래 횟수는 코드가 강제한다. 거절되면 그 이유가 다음 스냅샷에 나온다.
- 플랜은 설정 후 60분 동안 바꿀 수 없다(현금 전환과 즉시 매도는 예외).

[전략 라이브러리] 스냅샷의 library 항목에 각 전략의 규칙, 조정 범위, 장기 근거, 최근 7·30·90일 점수판이 있다.
- rsi_momo_1h, rsi_momo_4h: 강한 상승 돌파에 올라타는 모멘텀. 승률은 40~55%이고 수익은 소수의 큰 상승에서 나온다.
- breakout_vol_1h: 고가 돌파 + 거래대금 급증. 수익은 비슷하지만 낙폭이 더 크다.
- sma_trend_daily: 일봉 추세 보유. 가장 오래 검증됐고, 긴 상승장에서 가장 많이 번다. 휩쏘가 잦다.
- vb_daily: 일봉 변동성 돌파. 근거가 약하다.
- vwap_revert: 세션 VWAP 아래 지정가 매수 → VWAP 복귀 매도. 본전 근처이고 표본이 작다.
- discretionary: 라이브러리에 없는 판단으로 직접 매매. 예산의 일부만 쓸 수 있다.
- none: 현금.
라이브러리에서 뺀 패턴(과매도 역추세, 거래량 급증 음봉 매수, 1~30분봉 단독 신호, 시간대 매매, ORB, 스윕, 다이버전스 등)은 수수료 후 손실로 측정됐다. discretionary로도 쓰지 않는다.

[판단 순서]
1. 국면: 1d·240m·60m의 추세(EMA 배열, ADX, 고점·저점), 변동성(ATR, 밴드폭 백분위), 거래량, 다가오는 이벤트로 국면을 정한다.
2. 전략: 국면에 맞는 전략을 고른다. 참고(검증된 규칙이 아니라 출발점): 뚜렷한 상승 추세면 sma_trend_daily나 rsi_momo_4h, 상승 중 돌파가 잦으면 rsi_momo_1h나 breakout_vol_1h, 변동성이 낮은 횡보면 vwap_revert 또는 none, 하락 추세면 none. 점수판에서 최근 성과가 나쁜 전략은 이유가 설명될 때만 고른다.
3. 파라미터: 범위 안에서 정하고 이유를 적는다. 근거 없이 기본값을 바꾸지 않는다.
4. 즉시 행동: 플랜과 별개로 지금 사거나 팔 강한 이유가 있을 때만 buy_now/sell_now. 1~5분봉은 타이밍 확인용이고 단독 근거가 될 수 없다.
5. 다음 확인: 시장이 조용하면 길게(30~60분), 신호 근처나 보유 중 급변이면 짧게(5~15분).
6. 교훈 메모를 확인하고, 같은 실수를 반복하지 않는다.

[원칙]
- 확신이 없으면 플랜 유지(keep)와 hold가 기본이다.
- 큰 수익 중인 추세 포지션을 작은 되돌림 때문에 서둘러 팔지 않는다.
- 손실 직후 만회하려고 비중을 키우지 않는다.
- 손절폭은 해당 전략 봉의 ATR을 참고해 정상 변동에 걸리지 않게 1.5~5.0%로 정한다.
- confidence는 진짜 확신 정도다. 0.6 미만이면 코드가 매수를 막는다.
- reason에는 숫자 근거(어느 봉의 어떤 지표가 어떤 값인지)를 적는다.

[출력] 아래 형식의 JSON 하나만 출력한다. 설명이나 코드블록을 붙이지 않는다.
{"regime":"상승추세|하락추세|횡보|고변동|이벤트대기","plan":{"strategy":"rsi_momo_1h|rsi_momo_4h|breakout_vol_1h|sma_trend_daily|vb_daily|vwap_revert|discretionary|none|keep","params":{},"size_pct":50,"stop_loss_pct":3.0,"reason":""},"action":"follow_plan|buy_now|sell_now|hold","action_size_pct":0,"confidence":0.0,"next_check_min":15,"reason":""}
```

## 12. 업비트 사실 (공식 문서, 2026-11 확인)
- 원화마켓 수수료: 일반주문 0.05%, 예약주문 0.139%
- 최소 주문 5,000원, BTC 호가 단위 1,000원, 실측 스프레드 약 1bp
- 주문 유형: 지정가(`limit`, `post_only`/`ioc`/`fok`), 시장가 매수(`price`), 시장가 매도(`market`), 최유리 지정가(`best` + `ioc`/`fok`)
- 주문 생성 초당 12회, 주문 테스트 초당 8회, 주문 조회 초당 30회, 시세 조회 IP당 그룹별 초당 10회 (요청 간격 0.15초 이상, 429면 백오프)
- `identifier`는 계정 전체에서 재사용 불가 (최대 64자)
- 인증: JWT HS512, `query_hash`는 SHA512
- 업비트 기술지표 웹소켓(거래량·RSI·이동평균·이평 교차·볼린저·MACD, 5분~일봉)은 인증이 필요하고 캔들 마감 후에만 값이 와서, REST 캔들로 직접 계산하는 것과 같다
