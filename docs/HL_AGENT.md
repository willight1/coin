## 신호와 투표단

`bot/hl_live.py`·`bot/hl_signals.py`·`bot/hl_client.py`. 신호는 `research/leverage_2026-11/` 전수 측정에서 통과한 규칙들의 투표를 **분석가(추세·파생·거시·심리, `hl_rules.analyst`)별로 평균한 뒤 그 평균을 다시 같은 비중으로 평균**(`hl_signals.combine`, 노출 −1~+1) × 변동성 맞춤 배수(목표변동성 ÷ 20일 실현변동성, 상한 `HL_MAX_LEV`). 4시간봉 마감 20초 뒤 코인별로 목표 명목에 맞춰 재조정(지정가 먼저, 남은 건 시장가). **고정 배수는 쓰지 않는다** — 2~3배 고정은 측정상 전멸, 배수 다이얼은 `HL_TARGET_VOL`.

## 재조정과 주문 방식

- **재조정 완충 30%**(`hl_live.REBAL_BAND`): 같은 방향이고 목표와 차이가 목표의 30% 미만이면 안 맞춘다. 5배 하한에서 4시간마다 맞추면 회전율 연 500배·시장가 수수료 연 22%였다(`research/leverage_2026-11/more_rules.py` sim2, 1배 성적은 그대로).
- **지정가 우선**(`HL_MAKER_WAIT_SEC`, 기본 300, 0 = 바로 시장가): 재조정 주문을 최우선 호가에 post-only 로 걸고 5분 뒤 남은 수량만 시장가(`HlClient.maker_order`, 체결량은 계좌 포지션 변화로 센다). 기다리는 동안 틱 루프가 멈춘다(코인당 최대 5분). 정지·킬·절반·대기 명령은 바로 시장가(`urgent`). 측정(`maker_fill.py`): 연 비용 BTC 7.1→5.0%, ETH 5.9→5.4% — 못 채운 10%가 불리한 가격에 사서 이득은 작다. 취소가 확인 안 되면 시장가로 잇지 않고 알림만 보낸다.
- **시장가 안 쓰기**(`HL_MAKER_ONLY`, 기본 1, 2026-11-16 사용자 요청 — 시장가 수수료 0.045% 대신 지정가 0.015%): 재조정·명령(절반·대기·정지)·직접 주문 모두 지정가로만 건다. `HlClient.maker_order` 가 최우선 호가에 post-only 로 걸고 15초마다 호가가 앞서 가면 취소 후 다시 건다(따라가기, 최대 `HL_MAKER_WAIT_SEC`). 못 채운 것 중 포지션을 **늘리는** 몫은 버리고(다음 4시간 점검에서 다시 판단), **줄이는** 몫은 `state.pending` 에 목표 수량을 적어 틱(30초)마다 지정가로 다시 건다 — 급하게 빠져야 할 때 체결이 늦어질 수 있다. 시장가는 킬 드로다운 전량 청산(`flatten`, `market=True`)에만 남아 있다. 0 으로 두면 예전처럼 '지정가 5분 → 남은 건 시장가'.
- 가상 모드: 중간가 체결, 테이커 0.045%, 시간당 펀딩(롱이 내고 숏이 받음) 반영. 실거래: 공식 SDK `market_open`(IOC, 슬리피지 0.5%), 포지션·평가금액은 매 틱 계좌에서 다시 읽는다. 2026-11-14 실거래로 전환해 재조정·지정가 정리는 실주문으로 돌았다. 주문 방식은 아래 '시장가 안 쓰기'가 우선이라 `market_open` 은 `HL_MAKER_ONLY=0` 이거나 킬 드로다운일 때만 쓰인다.

## 안전장치와 알림

- **이익 보호**(`hl_live.guard`, `TRAIL_PCT`·`TRAIL_KEEP`): 거래(투표 방향이 같은 동안)의 최고 이익을 4h 종가로 추적하고, 거기서 5% 되돌린 종가로 마감하면 노출을 25%로 줄여 방향이 바뀔 때까지 유지. 5배에서 시작 시점 8구간 모두 크게 개선, 1배에서는 연수익을 깎는다(측정 `profit_guard.py`·`mtf_exit.py`, 스킬 기록). 익절 후 다음 날 재진입·여러 시간대 다수결 정리는 5배에서 전부 손실.
- **절반·대기 모드**(`touch state/HL_HALF` = 절반, `state/HL_WAIT` = 전부 정리, 2026-11-15 사용자 요청. 배수는 `state.half_k`): 그 순간 포지션 방향을 `state.half` 에 적고 바로 목표의 절반으로 맞춘다. 투표 부호가 바뀌면(새 추세) 지우고 전액. 추세 중간에 켰을 때용(측정 `fresh_start.py`·`split_entry.py`: 평균은 전액과 비슷, 중앙값은 나음).
- 알림(매매는 안 바뀜): 청산가까지 20/10/5% 안쪽 처음 진입, 1시간 ±3% 급변(코인별 1시간 쿨다운), 매일 09:05 요약. 펀딩비는 매시 거래소 `userFunding` 을 `state.funding` 에 누적, 체결마다 `userFillsByTime` 로 실현 손익·수수료를 `hl_trades.csv` 에, 재조정마다 노출을 `logs/hl_votes.csv` 에 남긴다. 체결 `side` 는 주문 방향이 아니라 포지션 변화 문구(`숏 줄임(일부 되사기)` 등).

## 명령·직접 주문·예약·분봉 단타

- **명령:** 텔레그램 `/hl_status`·`/hl_half`·`/hl_wait`·`/hl_stop`·`/hl_go`(포지션이 바뀌는 건 60초 안 `/hl_yes`). getUpdates 는 50일선 봇만 읽으므로 `trader.handle_command` 가 `state/hl_commands.txt` 로 넘기고 `HlBot.commands()` 가 매 틱 읽는다(**50일선 봇이 꺼져 있으면 텔레그램 `/hl_*` 가 안 먹는다**). 대시보드 '봇 설정' 탭 버튼(`/api/command` 의 `hl_*`)도 같은 파일. `/hl_go` 는 킬 드로다운 정지는 풀지 않는다.
- **직접 주문**(2026-11-16): `/hl_long 코인 금액`·`/hl_short 코인 금액`(금액 = 달러 명목, `10x` = 계좌 평가금액의 10배, `100 20x` = 넣는 돈 100달러 × 20배 = 포지션 2,000달러 — 2026-11-17 사용자 요청 "배수 선택해서 얼마 롱쳐". 크기만 정하는 것이고 교차 마진·거래소 배수 설정(상한)은 그대로라 손실이 넣는 돈에서 멈추지 않는다. 확인 문구에 그렇게 적는다. 대화에서 코인을 안 말하면 btc)·`/hl_close 코인`·`/hl_auto 코인`, 모두 `/hl_yes` 확인. 손댄 코인은 `state.manual` 에 적혀 `/hl_auto` 전까지 재조정·절반·대기가 건드리지 않는다(정지·킬 드로다운은 같이 정리). 이익 보호만 걸린다(사용자 요청): 같은 `guard` 를 포지션 방향·평균 진입가로 돌려 발동하면 75%를 한 번 정리하고 남은 25%는 그대로 둔다(`guard.trimmed`), 직접 주문이 체결될 때마다 다시 센다. 이익이 없어도 진입가에서 약 4.8% 불리한 4시간 종가면 발동한다. 확인 문구에 주문 뒤 예상 청산가를 보여 준다(`HlBot.liq_estimate`: 교차 마진 공식, 유지 증거금률 = 1 ÷ (최대 배수 × 2), 다른 코인 가격은 그대로라고 가정). 늘리는 주문은 거래소 배수 설정을 상한까지 올린다(교차 마진이라 청산가와 무관, 봇이 다음 주문 때 자기 값으로 되돌린다). **실주문으로는 아직 검증되지 않았다** — 처음엔 소액으로. `/hl_hold 코인`(2026-11-17 사용자 요청 "이더리움은 팔지 말고 거래만 중지, 비트코인만")은 주문 없이 그 코인을 같은 `state.manual` 에 넣는다 — 포지션은 그대로, 이익 보호 기록도 이어 간다. 멈춘 코인은 `state.hold` 에도 적혀 그 몫의 돈을 나머지 코인이 쓴다(`share = 평가금액 ÷ (코인 수 − 멈춘 코인 수)`, 같은 날 사용자 요청 "비트코인에 계좌 전액"). 멈춘 코인이 있으면 봇 주문의 거래소 배수 설정을 상한까지 올린다(멈춘 포지션이 증거금을 같이 써서 평소 설정으론 주문이 거절된다). 그날부터 실계좌 ETH 는 멈춤 상태이고 BTC 가 계좌 전액 기준으로 돈다(ETH 숏은 같은 날 18:37 사용자 지시로 `/hl_close ETH` 정리 — 직접 주문·지정가 정리 경로의 첫 실주문 확인, 지정가 100% 체결). `/hl_auto ETH` 로 되돌린다.
- **예약 주문**(2026-11-17 사용자 요청): `/hl_at 코인 가격 close|long 금액|short 금액`(가격 자리 `2%` = 평균 진입가에서 2% 이익, `-3%` = 3% 손실, 금액은 직접 주문과 같은 세 가지 — 달러·`10x`·`100 20x`. 대화에서 달러 없이 배수만 말하거나 '전액'이면 `10x` 꼴로 잡는다), `/hl_list`, `/hl_cancel 번호|all`. `/hl_yes` 확인 뒤 `state.resv` 에 적고, `HlBot.reservations` 가 틱(30초)마다 지금 가격과 견줘 닿으면 그 주문을 **직접 주문 경로(`manual_run`)로** 실행하고 지운다(그래서 실행된 코인은 `state.manual` 이 된다). 거래소에 주문을 걸어 두지 않으므로 재시작해도 고아 주문이 없지만, 30초 사이에 찍고 돌아온 가격은 놓치고 그 가격에 정확히 체결되지 않는다(코드의 `ponytail:` 주석). 정리 예약은 포지션이 없어지면 스스로 지운다. 대시보드는 코인 카드의 '예약 N번' 줄과 차트의 파란 점선으로 보여 주고, 거는 것은 텔레그램이나 아래 주문 대화창에서 한다. 연습용 계좌(`/hlp_at`)에서 걸기·목록·취소까지 실제 프로세스로 확인했고, **가격이 닿아 실행되는 것은 테스트(`check_commands`)로만 확인**했다.
- **분봉 단타**(`/hl_scalp on`·`off`, `HlBot.scalp`·`sync_stop`, 2026-11-17 사용자 결정 "하이리스크 하이리턴" — 측정 `research/leverage_2026-11/vote_1m.py` 에서 32개 조합 전부 탈락·20배는 9~25일 안에 99% 손실이라는 결과를 보여 준 뒤 사용자가 실계좌 자동매매와 거래소 손절(시장가 허용)을 골랐다. **다시 말리지 말고 사실만**): 멈추지 않은 첫 코인(지금 BTC)을 `state.manual` 에 넣어 4시간 재조정·이익 보호에서 빼고, 1분봉이 닫힐 때마다(`hl_tfboard.vote_share` = 방향판과 같은 가격 규칙 16개의 롱·숏 표 비율) 60%(`HL_SCALP_TH`) 넘는 쪽으로 계좌의 20배(`HL_SCALP_LEV`)를 지정가로 잡는다. 반대쪽이 넘을 때까지 들고 가고 넘으면 뒤집는다(측정의 방식 B). 같은 방향이면 목표보다 30% 넘게 모자랄 때만 채운다. 단타 코인은 지정가 대기가 40초(`SCALP_WAIT`)이고 거래가 끝나도 투표단 재선정을 안 띄운다. **손절은 거래소에 걸어 둔 시장가 트리거 주문**(평균 진입가에서 `HL_SCALP_STOP_PCT` 2% 불리한 곳, reduce-only, 포지션 전부 — '시장가 안 쓰기'의 두 번째 예외): 매 틱 `frontendOpenOrders` 로 거래소 주문을 직접 읽어 포지션과 다르면 취소하고 다시 건다. 포지션이 우리 주문 없이 사라지면(손절·청산) 투표가 반대쪽으로 넘어갈 때까지 그 방향은 쉰다(`scalp.block`). 끄면 포지션을 지정가로 정리하고, 다 정리된 뒤 손절 주문을 취소하고 상태를 지운다(코인은 `manual` 에 남는다 → `/hl_auto`). 단타 코인에는 직접 주문·예약을 못 낸다. 손절 주문은 재시작해도 거래소에 남고 다음 틱에 다시 맞추므로 **단타 손절 주문만 걸려 있는 상태의 재시작은 괜찮다**(지정가 주문이 걸려 있을 때만 피한다). 트리거 주문 형식은 실계좌에서 먼 가격·최소 수량으로 걸기·조회·취소를 확인했다.

- 대시보드 '시간대별 방향판'(`bot/hl_tfboard.py`, `/api/hl/tfboard` 60초 캐시)은 참고용. 1분~1시간 봉에 가격 규칙을 그대로 적용한 것이고 봇 매매에는 안 쓴다(짧은 봉은 측정 전부 탈락).

## 참고용 데이터 수집 (봇 판단에 안 씀)

- **시장 심리 기록(참고용, 봇 판단에 안 씀):** `research/hl_sentiment.py` 를 launchd `com.juno.hlsentiment` 가 매시 5분에 돌려 `logs/hl_sentiment.csv` 에 쌓는다(하이퍼리퀴드 수익 상위 지갑 롱·숏, 바이낸스 롱숏 비율·OI·펀딩). 같은 실행에서 고래 지갑별 포지션(실적 상위 = 이번 달·누적 상위 30, 실적 약함 = 계좌 100만$+·누적 손실 30)을 `logs/hl_whales.jsonl` 에, 대시보드 '고래 청산 지도' 요약을 `logs/hl_whales_latest.json` 에 쓰고, 실적 상위 순포지션 급변·1천만$+ 포지션 열림/정리를 텔레그램 `[고래 · 참고용]` 으로 보낸다(자체 점검 `research/hl_sentiment.py --selftest`). 지갑을 '지금' 순위로 고르므로 이 기록으로 과거를 재면 미래 정보다. 과거 기록을 받을 수 없는 데이터라 지금부터 모은다. 투표에 넣으려면 기록이 쌓인 뒤 같은 합격 기준으로 재고 나서. 코인니스 속보도 같은 성격: `research/coinness.py` 를 launchd `com.juno.coinness` 가 10분마다 돌려 `logs/coinness.jsonl` 에 쌓는다(키 없는 `api.coinness.com/feed/v3/breaking-news`, `endAt` 으로 2018년까지 과거 조회 가능, 끊기면 `--backfill` 로 이어 받기). 독자 호재·악재 수는 지금 누적값이라 과거 측정에 쓰면 미래 정보다. 측정 `research/leverage_2026-11/news_sweep.py`.
